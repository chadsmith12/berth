## 1. Headline answers

**Is it doing too much?** Not in the way most codebases are. There are no speculative frameworks, no dependency pile (3 modules in `go.mod`), and no layer that shouldn't exist. The "too much" is concentrated and specific:

1. **A previous audit's backlog sits unapplied.** `docs/REPORT.md` (2026-09-06) documents 31 accepted findings. I re-verified them against the current tree: **all 31 are still present and still accurate** (only line numbers drifted in two). The single biggest simplification available is not a new idea — it is executing that backlog.
2. **A dead-code layer has grown on top:** a write-only `Session.Token`, a never-read `launch.Result.PublicKey`, dead struct fields, an unreachable adopt branch, an unused `LookupEnv` seam, and two same-package helpers doing one job. ~10 small deletions.
3. **Sentinel values (`0`, `""`, `-1`) are the dominant defect theme.** Team id 0, workers -1, port 0, env "" all collide with real values — and one of these (team 0) is live in the actual `local-root` profile used against the test instance.
4. **The Coolify integration had never been checked against current docs.** This round did that (§4): one endpoint berth depends on is now a **deprecated alias**, one design-contract violation in launch, and several design-doc claims that no longer match reality.

**Can it be easier to read?** Yes, mostly by deletion: merging `composeDir`/`composeScanDir` (~80 duplicated lines in the 832-line `launch.go`), collapsing the `App`/`Command` duplication in `pkg/cli`, and single-sourcing rules that live in 2–4 places (env default, compose filename, variant matrix, config-file writers).

**Should we add dependencies to simplify? No.** The candidates were considered and rejected:

- *cobra/urfave-cli* to replace `pkg/cli` (301 lines): stdlib `flag` stops at the first positional, so `berth generate --json` (globals after the command — tested behavior) requires custom parsing anyway. The real waste is the *internal* `App`-vs-`Command` duplication (old finding P), which a rewrite fixes without a dep. Cobra would also rewrite every command for zero behavior gain.
- *A diff library* to replace `pkg/generate/diff.go` (158 lines): the LCS implementation is correct, tested, and zero-dep. A dependency saves nothing.
- *yaml.v3* is justified (genuinely parses compose files; there is no stdlib YAML) — but `go.mod:9` wrongly marks it `// indirect`; `go mod tidy` fixes the marker (verified with `go mod tidy -diff`).

**GUI-readiness:** the bones are right — commands are data-in/data-out, prompts are isolated to `pkg/input` (imported only by `pkg/commands`), `output.Emit` is the single render call, `launch.Inputs` is plain data, and `deploy.Follow`'s event channel matches design §3. Three things should happen *before* a GUI exists, while nothing consumes the JSON: the `FixView` shape change (old U), the logout view fix (old F), and removing CLI flag names from *library* error strings (`pkg/generate/generate.go:44,47` say "pass --port"/"pass --workers" — a GUI has no flags to pass; see NC4).

## 5. NEW findings (this audit round)

Each: what it does → why it's too much/wrong → how to improve → why that's better. Confidence / effort.

### API-facing

**NA1 — berth's one universal endpoint is a deprecated alias.** `client.go:43` calls `GET /teams/current`; current Coolify docs/spec know only `GET /team` ("Get the team bound to the API token"), and the v4.x route file labels `/teams/current` "Deprecated alias — remove in a later release." Every acting command flows through `VerifyTeam` → this path, so the day the alias is removed, *all* auth breaks at once. → Change one path string (`client_test.go:18` follows), update design §8's table. Probed: `/team` works on 4.3.19 today with an identical body. HIGH · trivial.

**NA2 — `resolveEnvironment` violates the refuse-on-duplicates contract.** `pkg/launch/launch.go:179-194` returns the *first* name match; `resolveProject` 15 lines above (154-177) implements the refuse-on-multiple switch the design doc demands for "project **or environment**" (`cli-design.md:384-385`). Coolify has name-or-uuid environment endpoints, so duplicates are representable; berth would silently pick one and record its uuid. → Mirror the `resolveProject` switch. HIGH · small.

**NA3 — design §8 claims detection code that doesn't exist; the real 403 misdirects.** `cli-design.md:658-660` says misleading-`success:true` failures (disabled API, IP allowlist) are "detected explicitly" — no such code exists (grep: nothing; `client.go:120` keys on status only). Current docs say the IP-allowlist rejection is a **403** with `{"success":true,...}` — so `error.go:39-40` renders "token lacks the required permissions," sending the user to fix abilities when the fix is the allowlist. §9's rule is "every error names the fix"; this one names the wrong fix. → Special-case a 403 body containing `not allowed to access the API` to name the IP allowlist, or delete the doc sentence. HIGH (doc is false today) · small.

**NA4 — 422 field errors are silently dropped.** `error.go:78-89` parses only `message` + `conflicts`; Coolify validation failures carry `errors: {"field": ["..."]}` (documented; 422 is on endpoints berth uses, incl. `POST /applications/private-deploy-key` for invalid domains). Today an invalid domain yields "[422] Validation failed." with the actionable field discarded — and launch sends user-typed domains, so this is the most likely 422 berth will ever hit. → Add `Errors map[string][]string` to the payload, flatten into `Message`. MEDIUM · small.

**NA5 — the port-502 rationale comment is wrong for the proxy berth actually runs against.** `pkg/launch/launch.go:270-277` claims a portless domain makes the proxy hit port 80 → 502. Source-verified on 4.3.19: ports are stripped from stored `docker_compose_domains` into `domain_port_overrides`, and Traefik's label generation falls back to the single exposed port — probed live: a portless stored domain serves **HTTP 200**. The 502 mechanism is real only under Caddy (renders `reverse_proxy {{upstreams}}` = :80). → Keep appending the port (correct cross-proxy behavior — berth can't know the server's proxy), fix the comment to say so. Side-effect worth knowing: because Coolify stores domains portless, `ComposeDomains()`/`berth status` display the domain without the port (observed in the live `berth status` run). HIGH (mechanism) · comment-only.

**NA6′ — `docker_compose_domains` spec divergence: document, don't change (pushback outcome).** The spec documents an array of `{name,domain,redirect}`; berth sends an object map (`resources.go:169`, `launch.go:136-138`). The change recommendation was withdrawn after pushback: §8 says probe beats docs, the object form is probe-proven (two berth-created apps deploy; one serves traffic), and source review shows no concrete failure mode (validation passes, normalization is shape-agnostic, nothing runtime-validates against the spec). → Add a comment on `CreateApplicationBody` recording the divergence **and** that the inner `Name` is load-bearing (the server keys storage by `data_get($domain,'name')`, not the outer map key). Re-probe only if a future Coolify rejects creation. HIGH · comment-only.

**NA7 — `/deploy?uuid=` is concatenated unescaped.** `resources.go:288`. Coolify uuids are URL-safe today, but `url.Values{}` is the same line count and removes the assumption. Also noted: the endpoint supports `force` (cache-less rebuild) — a feature gap to track, not a defect. trivial.

**NA8 — old finding K (SetEnvVar N+1) has a strictly better fix than previously known.** `PATCH /applications/{uuid}/envs/bulk` is documented as "Update" but v4.3.19 source (`create_bulk_envs`) proves it **upserts** — creates missing keys. K's fix collapses from "one list + N create/update round trips" to **2 requests total**: one `GET .../envs` (still needed for the APP_KEY-existence check) + one bulk PATCH. Caveats from source: a per-item validation failure 422s mid-loop after earlier items saved (partial application — keep fail-fast naming the key), and keys are normalized server-side (trim, spaces→underscores) — both fine for launch's pre-validated keys. Verify with a write-capable probe before adopting. HIGH · medium.

**NA9 — design doc §8's "GET envs lists keys without values" is stale.** True only for plain `read` tokens; with `read:sensitive` the probe returns `value` and `real_value`. Doc fix; no code impact.

### Dead weight (delete)

**ND1 — `Session.Token` is write-only in production.** `session.go:22`, set at `:110`; only tests read it (`session_test.go:53,72,122,216`). The client carries the token internally. → Delete the field (tests assert via the fake server instead). HIGH · trivial.

**ND2 — `launch.Result.PublicKey` is set and never read.** `pkg/launch/launch.go:67,109`; the CLI uses `keyChoice.PublicKey` (`commands/launch.go:269,281`). Two channels carry the same value and the library one is ignored. → Delete the field (or consume it and drop the CLI-side threading — pick one). HIGH · trivial.

**ND3 — dead struct fields:** `Server.Usable`, `Server.Reachable` (`resources.go:72-73`), `Deployment.ApplicationName` (`resources.go:305`) — never read (grep-verified). → Delete; re-add when a consumer exists. HIGH · trivial.

**ND4 — `ResolveOptions.LookupEnv` is a speculative seam.** `resolve.go:36,45-47`; no caller in `pkg/` or `cmd/` ever sets it (tests use `t.Setenv`). A GUI has a real process env too. → Delete the field, call `os.LookupEnv` directly. HIGH · trivial.

**ND5 — `input.Terminal` exports `In/Out/Interactive` for no caller.** `input.go:18-20`; only input.go reads them, and mutating `In` after `New` desyncs the private buffered reader bound at `:30`. → Unexport all three (rides naturally with old finding G, which deletes the reader field). HIGH · trivial.

**ND6 — two same-package helpers doing one job.** `defaultStr` (launch.go:827, used :130,:534) and `firstNonEmpty` (auth.go:481, used once at :133) are the same function. → Keep one name. HIGH · trivial.

### Duplication / doing the same thing twice

**NP1 — `composeDir` and `composeScanDir` are one algorithm written twice.** `commands/launch.go:408-441` vs `:454-486`: ~80 lines differing only in the file-existence predicate (specific env's compose vs any compose) and the error text. This is a third of launch.go's excess size. → One function taking a predicate (`hasCompose(dir, env)` / `hasAnyCompose(dir)`); error text parameterized. Also folds in the compose-filename single-sourcing (old X) since both construct `docker-compose.<env>.yml`. HIGH · small.

**NP2 — the three config writers are triplicated AND non-atomic.** `credentials.go:55-64`, `repo.go:121-130`, `userconfig.go:50-59`: identical marshal→newline→mkdir→`os.WriteFile`. A crash mid-write leaves truncated JSON — for `credentials.json` (0600, tokens) that is silent credential loss; and `os.WriteFile` applies `perm` only at creation, so an existing file with loose perms is never tightened. → One shared `writeJSON(path, perm, v)`: marshal, mkdir, temp file in the same dir, chmod, rename. All three Save functions become 3-liners. HIGH · small.

**NP3 — loader validation is asymmetric.** `LoadRepoConfig` and `LoadUserConfig` validate; `LoadCredentials` doesn't (duplicate team ids under one instance load silently; `FindToken` returns the first). `repo.go` validate rejects team id 0 while `profiles.go` allows it — and team 0 is real (the `local-root` profile). → Small `validate()` on credentials; decide the team-0 regime once (folds into old E's `*int` fix). MEDIUM · small.

### Correctness smells

**NC1 — `nodeVersion` has the same upper-bound bug class as old finding A.** `detect.go:385-403`: first-match regex on `engines.node`; `"node": "<20"` yields **20** — the upper bound used as the version. (Old A is the PHP twin: `readPhpVersion` returns 8.5 for `"php": "<8.5"`.) → Delegate to a constraint-floor parser like the PHP lock path's `minSatisfyingPhp`. MEDIUM (rare constraint shape, but the same silent-wrong-image failure class) · small.

**NC2 — dead `os.IsNotExist` disjunct + fragile string matching on the compose-file check.** `commands/launch.go:170`: `os.IsNotExist(fmt.Errorf("read %s: %w", ...))` is always false (`os.IsNotExist` doesn't unwrap `fmt.wrapError`); the check that actually works is `strings.Contains(err, "no such file")` — a string match on an OS error message. → `errors.Is(composeErr, fs.ErrNotExist)`; delete the string match. HIGH · trivial.

**NC3 — the SSR check/fix operates on *any* `'url'` key in `config/inertia.php`.** `check.go:124,143` match `'url' => ...` anywhere in the file, and `ssrFix` (`:164-186`) uses `ReplaceAllStringFunc` — a project with a second `'url'` key in that file gets all of them rewritten to `env('INERTIA_SSR_URL', ...)`. → Anchor the regex to the `ssr` array context (or at minimum replace only the first match). MEDIUM · small.

**NC4 — library errors name CLI flags.** `pkg/generate/generate.go:44` ("pass --port"), `:47` ("pass --workers"). `pkg/generate` is library code a GUI will call; flag names are a CLI concept (design §3: "No library code reads from stdin" is honored — but the error *text* leaks the frontend). → State the constraint ("application port must be set (1-65535)"); let the CLI layer append flag hints. (Related: old Z makes this a plan-check failure instead.) MEDIUM · trivial.

### Documentation drift

**NG1 — AGENTS.md documents a login URL chain the code doesn't implement.** AGENTS.md's auth section: "`--url` → `BERTH_URL` → repo config → user default → prompt (login)". `auth.go:133` implements only flag+env before prompting. → Either implement the chain (use the resolved URL as the prompt's default) or narrow the doc. LOW · trivial. (Compounds old AF/AG — AGENTS.md restating the design doc and drifting.)

**NG2 — `docs/REPORT.md` is committed and unactioned.** 31 findings, all verified still-accurate today. A report that isn't executed rots; either schedule the backlog or this document becomes the second copy of the truth. Meta, but real.
